# 旦生 Android 工作台开发计划 · 0.2

打开应用默认进入 eHall。校园办公、学习、资料搜索和论坛随客户端提供。当前只有「定时抢场」作为独立文件分发，可安装、启停和卸载。普通场馆查询、手动预约、查看记录和取消都不以安装插件为前提。

| 底部入口 | 功能安排 |
| --- | --- |
| eHall | 参考 DanXi 的首页卡片放置校园卡余额与明细、教室容量和空闲节次、宿舍电量。图书馆、食堂、校车、教务成绩和考试按服务进入。场馆按日期显示各场地和时段，支持手动预约与取消；校园邮箱先留未接入入口。 |
| eLearning | 日历放在最上方，可切换周／月；选中一天看课程、作业截止和个人日程。日历下方进入 Canvas 课程，浏览公告、作业、文件夹和文件。区分本科／研究生课表，教务与 Canvas 分别登录。 |
| Agent | 按账号搜索本机资料，回答附有出处；需要连接外部 AI 时，由用户开启只读本机 MCP 服务，并主动配对。 |
| 论坛 | 沿用 DanXi 树洞的分区、置顶、排序、搜索、主题和楼层；发帖与回复在这里完成。 |
| 插件 | 管理唯一的定时抢场插件。系统选择文件，Material 3 面板预览来源与能力；安装默认关闭。启用后，在 eHall 已选场地和时段上多出「创建定时任务」；关闭后手动操作照常。 |

**实施顺序与验收**

1. 建五栏导航和统一的视觉样式。默认页、未登录状态、暗色与大字号都应可用；邮件等尚未接入的入口明确说明状态。
2. 接通校园和学习数据。检查卡片能展开，课程、作业能落到正确日期，课程资料可以打开。某个服务登录失败不应阻断其他栏目。
3. 接通论坛与本地搜索。验证分区到楼层的浏览流程，以及搜索结果的出处；切换账号后，上一账号的数据与 MCP 配对不可继续使用。
4. 验收场馆的两种使用方式：全新安装可手动预约；导入后默认关闭，启用才可定时，关闭或卸载后可继续手动预约。超时先核对记录，避免重复提交。
5. 用合成校园页面在 Android 模拟器验证，分别记录 ARM64 构建、模拟器结果和真实学校账号验证。后续实机重点是学校认证、场馆规则和厂商后台唤醒；真实写入须单独授权。

客户端维护在同级 `dansheng-app`。Flutter 负责业务界面，Kotlin 提供系统文件选择、原生确认面板、登录 WebView、闹钟与通知；Rust Core 负责账户、数据、权限与任务状态，校方接口留在官方连接器。需要校园登录态的请求在已验证的页面里执行。DanXi 仅作只读参考，不复制用户数据或构建产物。

[旧版插件原型计划](android-app-plan-0.1.md)保留为历史记录。当前实现和测试边界见客户端的 `docs/workbench-validation.md`。

0.2.1 补充验收：首次登录后，设备用 Android Keystore 保存分账号的凭据；进程退出后恢复、用户退出后清除。真实读取与离线预约分开检查，客户端发布目录的 `CAMPUS-READONLY.json` 记录每项实际结果。
