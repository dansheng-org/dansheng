# Android 0.1.0 内测验收记录

这是旧版记录。[Android 0.2 工作台](workbench-validation.md)将手动场馆服务移入 eHall，只有定时预约仍属于独立插件。

客户端和抢场插件是两个独立产物。手机安装 `dansheng-android-arm64-beta.apk` 即可使用客户端；体育入口只在另外导入并启用 `official.fudan-sports-0.1.0.dspack` 后出现。模拟器使用 `dansheng-android-x86_64-debug.apk`。安装、升级与摘要核验见[使用说明](../README.md)及发布目录的 `SHA256SUMS`。

| 验收项 | 实际结果与边界 |
| --- | --- |
| 独立交付 | APK 内没有抢场包、其 JS 模块、场馆地址或预约提交端点。插件包有 9 个 UI 声明、18 个动作，仅 3 个运行时 JS 模块；构建工具和测试用的 Node 代码不随插件分发。同一来源独立打包两次，字节相同。 |
| 安装与开关 | 系统文件选择器导入后默认关闭；原生摘要输入、权限确认、启用、禁用和卸载均走过实际界面。产品仪器测试另核对 Core 注册表：未启用时拒绝动作，启用后用 QuickJS 读任务，禁用后再次拒绝，卸载后注册表无此插件。 |
| 界面 | Flutter 静态分析通过。9 个 widget 用例覆盖无插件、两种声明、零字段按钮、旧/未知版本处理、表单交互、切换账号、任务列表、窄屏与大字，以及中文 Material 控件和无障碍触摸标签。Android 无障碍树用于验收开关；未把自动检查当作真人 TalkBack 试用。 |
| 进程与核心 | 真正的 Flutter 客户端通过 Pigeon 和 JNI 调用 Rust；合成账号执行一次受限的本地 HTTP GET，生成来源记录与动态卡片。强制停止并打开新进程后，缓存保留，未持久化的凭据消失。 |
| 体育正常流程 | 产品宿主用当前外部包和被禁止访问网络的系统 WebView 测试。拒绝错误学工号，重新验证匹配账号；读取场馆、日历、预约和详情。预热任务与后续任务分开持久化；合法模拟预约恰好发送一次 POST。不允许的写入零 POST。 |
| 体育中断与恢复 | 模拟提交时断网：已发一次的请求进入 `needs_reconciliation`，重复操作不重发；停止另一个实际待运行计划，撤销其后续任务。在新进程里仍不能直接取消待核对记录。进程回收后，原生入口能恢复 Core，但不会恢复页面身份；过期会话记为 `waiting_for_auth`，写入认领数没有增加。 |
| 闹钟与 Android 兼容性 | API 36：无精确权限时任务已保存且 `not_armed`；授予后，同一任务重新注册；关闭插件撤销闹钟。API 28：验证数字时区偏移的解析、系统实际唤醒和前台服务启动，并在重启专用模拟器后观察到已安排任务执行一次。记录的时间偏差仅适用于这些测试，不保证校方收到请求的时刻。 |
| 系统权限与私有数据 | 凭据使用应用私有 Android Keystore；合成密文损坏时访问失败。拒绝通知权限返回明确错误。前台启动被拒的适配分支用注入的拒绝验证；不能据此外推厂商省电策略。 |
| 校园卡 | 单独使用官方连接器的卡服务登录与余额读取，密码不传入插件或 Dart。账号切换使旧会话失效。本轮验证了服务权限边界及禁止将登录保存成原生任务；未把 Windows 上的历史查询视为 Android 真实余额查询成功。 |
| 内测包 | ARM64 内测包签名有效，x86_64 验证包可安装。核对 APK 内原生库和对应 AAR、ELF 架构及 16 KB 对齐，确认没有测试页、私钥或内置浏览器运行时。APK 附带 Core 许可和原生依赖声明。 |

**验证范围：** ARM64 包已交叉编译、签名并静态检查，未在 ARM64 真机运行。没有真实学校登录、预约、取消或发信；校园身份探针来自学校公开客户端契约，在受控页面验证。真机 60 Hz 下的帧时间、厂商后台策略及实际校园响应仍需单独验证。独立的真机性能基准见 `bench/`，不进入产品包。

可重跑的模拟器入口是 `scripts/verify-product-emulator.ps1` 和 `scripts/check-wake-recovery.ps1`。发布目录的 `BUILD-INFO.json` 将 APK、独立插件与测试收据关联；本机逐阶段原始记录保存在 `.local/acceptance/`，不包含校园凭据，也不作为产品资源打包。
