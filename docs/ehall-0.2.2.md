# eHall · Android 0.2.2

| 入口 | 行为 |
| --- | --- |
| 校园卡 | 顶部卡片直接打开交易明细；刷新图标只更新余额。 |
| 教室 | 首次点卡片读取今日教室数量，再点进入详情。选择校区、教学楼、日期，也可筛选具体教室。每行给出容量和 13 个节次，绿色为空闲、红色为占用，未知不显示为空闲。 |
| 寝室电量、图书馆、食堂 | 第一次点卡片读取并显示数据，成功后再次点击进入详情。失败可以重试。寝室详情列出信息门户的实际用电记录，可分页，没有虚构的充值记录。 |
| 食堂认证 | 在“校园双因素认证”中打开学校页面。入口由 `my.fudan.edu.cn` 自行跳转到学校当前的 `id.fudan.edu.cn` 认证页，每次打开最多自动填入一次已保存的密码。短信或 OTP 由用户在校方页面完成后返回刷新，用电历史可以复用同一门户会话。 |
| 场馆 | 已保存统一认证密码时，在隐藏 WebView 中自动登录并核对账号，不打开网页；读取时会话过期也会静默恢复一次，并发读取共用一次登录。没有可用密码时先用原生密码框询问。只有学校要求验证码、双因素认证或拒绝密码时，才在同一个页面显示校方网页，且不再自动提交。密码送出后登录失败会暂停自动使用已保存的密码（保存在本机，重启后仍生效），直到学校再次接受密码或用户手动登录成功，避免触发锁号。不会经由教室 WebVPN 代理，也不会把网页跳转本身当作登录成功。 |
| 校车 | 按始发校区、终点校区、工作日／节假日筛选，可以互换方向或显示全部班次。行内方向使用与互换按钮同系列的图标。 |
| 教务公告 | 顶部在本科生和研究生之间切换，列表分别来自教务处和研究生院，可打开单条原文；右上角可打开当前身份对应的官网公告栏。 |
| 设置 | 移除“无障碍”设置项，仍遵循系统字号并保留逐节状态的文字标签。 |

对照使用本地旦夕 1.5.3 Android APK；教室和校车的原页面在隔离副本中以离线样例运行，未修改 DanXi 检出目录。体育登录另在真实预约站验证，因为访客也能读取部分场馆信息。预约站发布的客户端明确使用 `/reservation/api/login/main` 返回业务页；真实身份检查使用同一 WebView 中的只读个人资料请求。

`CAMPUS-READONLY.json` 记录真实账号读取结果；`BUILD-INFO.json` 将它们绑定到设备上实际安装的 APK。界面验收只保存公共教室和校车的截图，不导出账号、卡余额或用电记录。真实测试不执行预约、取消、发帖或邮件发送。原生窗口的离线测试让用户停留超过旧的 50 秒时限；缺少真人验证码时，不把打开 2FA 页面算作已经通过第二因素。

在 API 36 模拟器的实际账号下，教室查询返回 28 间，校车接口返回 135 条记录，寝室余额可读。前台体育认证从预约站跳到学校身份站并返回，核对当前账号后读到 25 个场馆和场次。信息门户要求交互验证；本次没有代填验证码或读取验证后的个人用电历史。教室与校车的对照截图在发布目录的 `preview/ehall-comparison.png`。
